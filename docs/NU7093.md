# Arn0 for Samsung UE55NU7093UXXH

Target profile: Samsung NU7093, 2018, Tizen 4.0, firmware
`T-KTSUDEUC-1400.2`, reported by the user after updating the TV. The firmware version is
user-reported; the UE55NU7093 model was verified through Samsung's network API.
This edition runs as a regular app: Home continues to open Samsung Smart Hub.
The developer connection confirmed Tizen 4.0. Public signing, installation of version
0.6.13 and the launch command succeeded. The user verified the clock, app row, two HDMI tiles,
arrow-key focus and app launch with OK on the real TV. Home opens the same Samsung bar at
the bottom of the screen as before installation. The user also confirmed that the HDMI
buttons work. Performance, audio/video formats and Game Mode have not been measured.

## Changes

- Clock formatting without `String.padStart`, which Chromium 56 on the 2018 TV does not provide.
- Column layout using Flexbox, without requiring CSS Grid or flex `gap` support.
- System font and reduced navigation motion; navigation sounds are initially disabled.
- Date locale defaults to `it-IT`; HDMI ports 1 and 2 have neutral names.
- Installed apps are matched by name as well as ID, which varies by year and region.
  Regular YouTube, Netflix, Prime Video, Disney+, Spotify, RaiPlay, Mediaset Infinity and
  Apple TV appear only when found. This project does not install those services.
- If the firmware cannot open Samsung's viewer after selecting HDMI, the app asks the user
  to press SOURCE. Selecting a source alone does not verify playback.
- Back on the home screen offers to close the app; Settings also includes an exit command.
- The NU7093 compatibility report in Advanced shows detected capabilities. It distinguishes
  the configured profile from data actually read from the TV. Unavailable firmware is not a match.

## Live TV

Starting with version 0.6.14, the first tile in the sources row opens live TV.
Select it with the arrows and press OK: Arn0 selects the `TV` source reported by Samsung
and opens the tuner viewer, using channels already tuned on the TV. It does not scan for
channels, change the channel list or use an Internet stream.

If the firmware cannot open Samsung's viewer, Arn0 displays the signal through its own video
plane; Back then returns to the launcher. The antenna connection and channel tuning must
already be configured. A missing TV source or an opening error produces an on-screen message.

The shortcut is independent of the saved HDMI list, so it appears when updating an existing
installation without resetting preferences. In `src/js/config.js`, `liveTv: false` hides it;
`liveTv.label` and `liveTv.method` customize its label and opening method.

Version 0.6.14 was signed with the same certificate, installed as an update and launched
on the NU7093. The user confirmed both terrestrial channel playback and channel changes
with the remote on the real TV. Returning with Back from the alternative video plane was
verified only with simulated APIs, not on hardware.

Development checks: nine automated tests (`npm test`) cover ES5 compatibility and regressions,
including the TV source reported by the device, a missing viewer and rejected API calls.
A separate Playwright check with simulated APIs covered navigation to the TV tile, repeated-OK
protection, existing saved HDMI preferences, the alternative display mode and Back, a missing
tuner error and the 1080p/720p preview. Navigation and repeated-OK protection are covered by
that separate browser check, not by the repository's unit tests.
The build and independent code review completed successfully.

## Windows preview

Requires Node.js 20.11 or later and Python 3. From a terminal in the project directory:

```powershell
npm.cmd run preview
```

Open `http://127.0.0.1:8080`. Arrow keys and Enter simulate the remote; Esc/Backspace is Back.
Apps and inputs in the preview are simulated. The preview does not contact the TV.
The home screen is rendered at 1920x1080 and scaled to the 4K panel by the TV.

Once installed, the launcher and live TV shortcut run on the TV. No always-on PC or server
is required. The local preview server is used only for development.

To rebuild the package:

```powershell
npm.cmd run build
```

Output: `dist/arn0-launcher.wgt`. The build uses Node and Python's standard library,
without requiring `sh`, `zip` or application dependencies. For JavaScript development tests:

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
```

## Installing as an app

The generated `.wgt` is **unsigned**. Samsung signing depends on the certificate and device;
renaming the file or copying it to a USB drive does not make it installable.

1. Connect the PC and TV to the same network. Note the TV's IP address.
2. On the TV, open Apps and enter `12345` with the remote. If Developer Mode appears,
   enable it, enter the PC's IP address and restart the TV as instructed by that screen.
   Use the regular Apps menu, not the service menu.
3. Install using **Custom WGT File** in Apps2Samsung, which handles signing according to
   its configuration, or use Tizen Studio, Samsung TV Extension and a Samsung TV certificate
   profile valid for the TV's DUID. Follow the tools' documentation; no certificate is included
   here and signature checks must not be bypassed.
4. Open **Arn0 NU7093** from the app list. Test startup, arrows, OK, Back and Home first.
5. Check Netflix/YouTube and other installed services. In Settings > Apps on Home, add,
   remove and reorder shortcuts. Restart the app to confirm that changes are saved.
6. Test HDMI 1 and HDMI 2 separately with connected devices, including the SOURCE key.
   If needed, change the opening method in the HDMI input settings. Preservation of Game Mode
   or other features has not been verified on this TV.
7. If something fails, press Home to return to Samsung. The app can be uninstalled through
   the regular settings; uninstalling deletes Arn0's local preferences.

Keep the same author certificate for updates. A different signature can require reinstalling,
which deletes preferences. Local settings can be customized in `src/js/config.local.js`, following
`config.local.example.js`, before building.

This installation used Apps2Samsung CLI 3.1.0, creating a Public certificate for the TV through
the user's Samsung account login. Signing material is stored in the installer's data directory,
separate from the source and distributed archives. Preserve that directory to sign future
updates with the same author.

The app keeps the ID `Arn0Lnchr0.Launcher`, which the Apps2Samsung catalog recognizes as
Arn0 Launcher. To update **this adapted edition**, use the local WGT rebuilt from its source:
a package from the original catalog can replace the NU7093-specific changes.

## Home button and power-on

The original `native/` helpers target only the Q70B with firmware `T-PTMDEUC-1720.7`.
**Do not use them, change their checks or copy their values to the NU7093.**
This edition does not change system preferences, automatic startup or the Home button, and
does not require root. Any future Home-button work requires separate research on the actual
firmware and a tested recovery procedure. Installing the app alone does not establish feasibility.

### Device checks on 2026-11-01

Opening Arn0 with the physical Home button could not be enabled through the current developer
setup. The following checks were made on this NU7093, independently of the Q70B procedure:

| Check | Observed result |
| --- | --- |
| SDB platform and architecture | Tizen 4.0, ARMv7, sdbd 2.2.31, plugin 3.4.1_TV_REL |
| Developer execution capabilities | `intershell_support`, `sdbd_rootperm`, `rootonoff_support` and `appcmd_support` disabled |
| Harmless `sdb shell id` probe | Rejected with `closed` |
| Supported remote keys inside Arn0 | No Home key reported by `tizen.tvinputdevice.getSupportedKeys()` |
| Web service feature | `tizen.systeminfo.getCapability('http://tizen.org/feature/web.service')` returned `false` |
| TV-local application status | Arn0 returned HTTP 200 with running/visible state; Samsung Home (`com.samsung.tv.csfs`) and the TV viewer returned HTTP 404 |

The native helper transport used by the original project was unavailable in these checks:
`0 appinstall` without a package was also rejected with `closed`. A similar transport limitation
was independently reported for the 2018 UE43NU7099 in
[CleanFrame PR #8](https://github.com/nthnclrk/CleanFrame/pull/8).

The `web.service` capability is an advertised feature flag, not conclusive evidence that a
background service cannot run. Follow-up research found
[Vetro PR #75](https://github.com/andrearicci93/vetro/pull/75), an open, unmerged contribution
reporting a working Node 4.4.3 service on a UE43NU7090 with firmware 1400.2 after compatibility
fixes. That report does not establish root, remote remapping or support on this NU7093.
The stock Vetro root integration remains unavailable on the reported older runtime.

A TV-local service adapted to Node 4.4 therefore remains a candidate for investigation, including
the foreground-return approach used by [Skylight](https://github.com/SaudSatopay/skylight-tizen).
It has not been tested here. A working service alone would not prove reliable Home handling:
Samsung Home must be distinguished from active apps, the tuner and HDMI before automatically
bringing Arn0 forward. There is no tested one-press implementation for this device yet.

No native helper or Home-setting write was attempted. The temporary app debugging session was
closed and Arn0 was launched normally afterward. Home continues to open Samsung's original bar;
this fork does not currently provide a tested one-press replacement on the NU7093.

For quicker manual access, Samsung provides **Add to Home** and app reordering in its app settings.
If available for Arn0 on the TV, add it to the bar and move it near the beginning. Opening it then
uses Home, selecting Arn0 and OK. Menu placement varies by TV software; see
[Samsung's app management guide](https://www.samsung.com/us/support/answer/ANS10005205/).
