# Arn0 for Samsung UE55NU7093UXXH

This fork targets the 2018 Samsung NU7093, Tizen 4.0. Firmware
`T-KTSUDEUC-1400.2` was reported by the owner after updating. The TV itself reported
`BUILD.model = UE55NU7093` and
`BUILD.buildVersion = TIZEN-4.0-TRUNK2018-KantSU-RELEASE_20260605.1`.
These exact model/build values and Node 4.4 are required by the Home-return service;
an unrecognized profile leaves it disabled. This is not a compatibility claim for other TVs.

The owner verified the clock, arrow navigation, app launch, HDMI 1/2, terrestrial TV
playback and channel changes. Audio/video formats, input latency and Game Mode have not
been measured.

## Home and SOURCE in version 0.6.15

A small Node 4.4 service **inside the TV** watches a read-only application-context getter.
When Samsung's Home/source bar opens, it brings the existing Arn0 application forward.
The Samsung bar may appear briefly before Arn0. This does not remap or intercept the key.
It does not use root, the original native helpers, or system preference writes.
No PC, browser preview, external server or permanent SDB connection is required during use.

On this firmware, Home and SOURCE produce the same context bit (`0x100`). Both therefore
open Arn0, as accepted by the owner. Original SOURCE cannot be preserved independently
with this signal. HDMI and live TV remain accessible through Arn0's source tiles.
Volume produced a different signal and did not trigger the return in the recorded tests.

The owner confirmed physical Home from terrestrial TV, another app and Arn0 itself;
the Samsung bar disappears. Both Home and SOURCE also passed the continuous-service test.
On version 0.6.16, the owner also confirmed a rapid repeat: after the first return,
waiting two seconds and pressing Home again returned to Arn0 within about five seconds.
This final hardware check was performed with the PC development services closed.

- **Settings > Home button:** toggles the service's return behavior. Off is saved in this
  widget's private storage and survives service restarts. It leaves ordinary Samsung menus available.
- **Settings > Samsung Home:** exits Arn0 and pauses automatic return for two minutes.
  The owner verified that Samsung's original menus remain usable during this pause.
- Confirming **Back > close** uses the same two-minute pause.
- After a pause, a new closed-to-open transition is required; an already-open bar is not hijacked.
- Two valid samples are required, with bounded polling, a launch timeout and a cooldown.
  A failed read or unsupported profile does not trigger an app launch. A rapid second press
  during the cooldown is deferred until it expires, rather than silently lost.

The manifest requests service startup after a full reboot (`on-boot="true"`) and disables
automatic restart (`auto-restart="false"`). A Partner distributor certificate is required
for the boot-start request. The owner verified a full restart (holding Power until the Samsung logo), then Home
opened Arn0 without opening the app manually and with the PC developer connection closed.
Opening Arn0 manually also starts the service. A boot request alone should still not be treated as proof on a different device.

The service listens only on TV loopback, `127.0.0.1:8133`. Controls require a fresh per-build
token injected into the package, never written into tracked source. It runs one fixed
read-only `dbus-send` getter; callers cannot supply commands or application IDs. Its only
persistent write is `arn0-home-return.json` in this widget's `wgt-private` directory.
Launcher preferences remain in their original localStorage entry.

## Compatibility changes

- ES5 runtime syntax and clock formatting without `String.padStart` for Chromium 56.
- Flexbox column layout without CSS Grid or flex `gap` requirements.
- System font, reduced navigation motion and navigation sounds disabled by default.
- Date locale defaults to `it-IT`; HDMI ports 1 and 2 have neutral names.
- Installed streaming apps are matched by ID or name, including year/region variants.
  The launcher does not install those streaming services.
- Input selection handles a missing native Samsung viewer and reports failures.

## HDMI device identification: CEC trial

The owner confirmed that Samsung Anynet+ and Fire TV Stick HDMI-CEC control were already
both enabled. A fresh HDMI 1 disconnect/reconnect was tested with the Fire Stick powered.
The TV correctly moved HDMI 1 between the disconnected and connected source lists.

The source objects still exposed only `type` and `number`; no name, vendor or model was
returned, including immediately after reconnection. `SOURCE_INFO` was rejected with
`TypeMismatchError` on this runtime. The owner also reported that Samsung's source menu
showed the generic HDMI 1 label before this reconnect trial.

`tvwindow.getSource()` continued to report HDMI 1 while unplugged: that is the selected
input, not proof of a connected device. Use the `VIDEOSOURCE` connected/disconnected lists
for connection status. Read-only inspection of the HDMI/CEC driver directories exposed
no remote-device-name attributes. No driver controls or system settings were written.

This trial did not establish automatic Fire TV identification for Arn0. A saved mapping
from HDMI 1 to Fire TV Stick with an icon would be a manual association, not automatic
recognition. Application code was not changed for this trial. The temporary diagnostic
observer and debug connection were removed afterward.

## Live TV

The first source tile opens channels already tuned on the TV. It selects the reported `TV`
source and opens Samsung's tuner viewer. It does not scan channels, alter the channel list
or use an Internet stream. The owner confirmed playback and channel changes on hardware.

If the native viewer cannot open, the launcher can use its own video plane; that alternative
and its Back behavior were tested with simulated APIs, not on this hardware.
An antenna connection and existing channel tuning are required.

The shortcut is independent of saved HDMI preferences. In `src/js/config.js`, `liveTv: false`
hides it; `liveTv.label` and `liveTv.method` customize it.

## Preview, tests and build

Requires Node.js 20.11 or later and Python 3 on the development computer:

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
npm.cmd run preview
```

Open `http://127.0.0.1:8080`. Arrows and Enter simulate the remote; Esc/Backspace is Back.
The preview does not contact the TV and does not run the Home-return service.
The stage is 1920x1080 and the TV scales it to the 4K panel.

```powershell
npm.cmd run build
```

Output: unsigned `dist/arn0-launcher.wgt`. Signing keys, device profiles and passwords must
stay outside the repository and source archives. Each build generates matching control
tokens for the packaged UI and service. Do not hand-copy only one of those files.

## Installing or updating

1. Connect the PC and TV to the same network. Enable Developer Mode in **Apps > 12345**,
   enter the PC's IP and restart as instructed by the TV. Use the regular Apps menu.
2. Sign the locally built WGT with a Samsung certificate valid for the TV's DUID.
   Use a **Partner distributor certificate** for the requested service boot start.
   Apps2Samsung CLI supports `install <local-wgt> --partner --launch`; Tizen Studio can
   also sign and install. No signing material is included here.
3. **Keep the original author key for updates.** Changing from a Public to Partner
   distributor does not require changing the author. A new author caused update error
   `118012` on this TV. Retaining the original author with the Partner distributor allowed
   an in-place update without uninstalling or resetting preferences. Keep a private backup
   before changing certificate profiles. See [Samsung's certificate guide](https://developer.samsung.com/smarttv/develop/getting-started/setting-up-sdk/creating-certificates.html).
4. Open **Arn0 NU7093** once and verify apps, arrows, HDMI and live TV. Check **Settings >
   Home button**. An unsupported model/build or storage error leaves automatic return disabled.
5. Test Home from an app and from live TV, SOURCE, and **Settings > Samsung Home**.
   Separately test a full TV restart; ordinary standby is not proof of boot startup.

The application ID stays `Arn0Lnchr0.Launcher`; the service is `Arn0Lnchr0.HomeWatch`.
Use the WGT built from **this fork**: an original catalog package can replace the adaptation.
Before updating a running service, stop it through the current authenticated `/stop` control
using a temporary developer connection. It does not automatically restart. Then install and
open the updated package; this also avoids keeping an old per-build control token alive.
In the currently installed widget's Web Inspector console, the stop request is:

```js
var request = new XMLHttpRequest();
request.open('POST', 'http://127.0.0.1:8133/stop?token=' + window.ARN0_HOME_TOKEN);
request.send();
```

Wait for HTTP 200 before installing. Use the current TV widget, not the PC preview or a
newly rebuilt package, so the request uses the running service's token. Do not publish tokens.

To restore original Home/SOURCE behavior, turn **Settings > Home button** Off. No system
baseline or native restore helper is needed. Uninstalling Arn0 also removes its service
and private data, including saved launcher preferences.

## Device checks on 2026-11-01

| Check | Observed result |
| --- | --- |
| SDB platform | Tizen 4.0, ARMv7, sdbd 2.2.31 |
| Native helper transport | Standard shell and `0 appinstall` rejected with `closed` |
| Web-service feature flag | Advertised `false`, but an actual Node 4.4.3 service ran as UID 5001 |
| Native Home/TV-viewer HTTP status | Returned 404; unsuitable for detecting Home |
| Read-only app-context getter | Works without root |
| Probe foreground | `262176` (`0x40020`) |
| Home / SOURCE over probe | Both `262432` (`0x40120`) |
| Home from native TV / another app | Also carried `0x100`; base values differed |
| Volume | `8388640` or `32`, without `0x100` |
| Input-device permission probe | Read-only opens denied; no events read or grabbed |

The isolated diagnostic (`experiments/home-probe`) is short-lived and explicitly armed.
It was removed from the TV after successful trials. Diagnostic output and signing data
remain private and are not included in the repository.

The original `native/` helpers are guarded for Q70B firmware `T-PTMDEUC-1720.7`.
**Do not run them or weaken their guards for this TV.** The working approach here uses
the TV-local service instead. The old advertised feature flag was insufficient evidence
to rule out a service; [Vetro PR #75](https://github.com/andrearicci93/vetro/pull/75) supplied
the older-runtime lead, followed by direct testing on this NU7093.
